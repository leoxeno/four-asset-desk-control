# Results

Written 13 October 2026, in passes: this first pass after treatment v1, then a pass after each change to the map, then the outside check. Nothing from an earlier pass is removed; later passes add to it and say so. The scoreboard block is generated by `tools/score.py` from `grading.yml`; no count in it was typed by hand. Grading rules were committed before any run, in `questions.md`. A private pilot of the same design preceded this repo and is disclosed in `ABOUT.md`; nothing here was copied from it.

## The one line

Against nothing, the folder won every question that needed the data and tied the two that did not: the bare model answered 2024's best asset from memory, refused October 2026 for the right reason, and declined the other five, inventing nothing. What the folder cost was reading: with the first map it opened all seven of its files on every one of its sixteen answers; one line in the map cut that to four, and once cut too far.

## What was compared

Two arms, same model (`claude-opus-5-5`, effort high), same eight prompts, same tools, same no-network sandbox, one fresh session per question, eight questions at a time, two runs per arm. Every setting is in `PROTOCOL.md`.

- **control**: no folder, no files. The brief's "no folder".
- **treatment-v1**: the five-file folder, with the first version of its map.
- **treatment-v2** (second pass): the same folder with the second map, which tells the reader what not to open. Nothing else in the folder changed.
- **treatment-v3** (third pass): the same folder with the third map, which sends the refusal route through `rules.md` too. The folder that ships.

## Where the folder lost or tied

- **It tied on the question memory can answer and on the trap.** The bare model knew that gold beat stocks in 2024 and put GLD at 26.7% in both runs, the key's number. On October 2026 it refused in both runs, with two reasons: the month was not over and it had no data. Two of the eight questions needed no folder, and the trap caught nobody.
- **One win is a grading call.** On GLD's 2025 return the bare model said "about +63% to +65%" in one run and "roughly 63 to 65%" in the other. The key is 63.7% with a 0.3 point tolerance, and neither end of the range is inside it, so under the pre-registered rule the answer is partial, not correct, and the folder's 63.7% is a win. A reader who takes the range as "about 64" would call it a tie, and the folder's score becomes five wins and three ties. The rule was written before the runs and I apply it as written. The pilot's bare model said "about 64%" on this question and was graded correct there; the verdict moved with the model's wording, not with the grader.
- **It read more.** All sixteen folder sessions opened all seven files: `README.md` first, as instructed, then `identity.md`, `rules.md`, `examples.md`, the methodology, the data dictionary and the price file, either in one `cat` or one `Read` at a time. The map's route table names the two or three files a numeric question needs, but the map's own "Next" line sends the reader to `identity.md` every time and nothing says to stop. Seven files against zero for the bare model, which had nothing to read. That is the one place the folder cost more, and it is what the next change to the map is for.
- **It was not slower, but one run took more turns.** Median seconds per answer: folder 23.7 and 26.4, bare model 28.4 and 27.6. Median output tokens: folder 1,221 and 1,462, bare model 1,594 and 1,416. In the folder's run 2, five of eight sessions opened the files one at a time with the Read tool, ten turns against four; seconds moved by about three. The bare model's answers were the longest because they spent their words on what they could not do and how the reader could do it instead.
- **v2 cut the reading and, once, cut too far** (second pass). With the second map, fifteen of sixteen sessions opened exactly the four files the route table names, `README.md`, `rules.md`, the methodology and the price file, and the sixteenth opened three. That sixteenth was run 2, question 8: the v2 route for a month outside the window names only methodology section 11, so the model never opened `rules.md`, refused October correctly, with the reason and no figure, and ended without the fixed answer line, because the line is defined in the file it did not open. Content right, shape wrong: a map that routed too narrowly. Under the pre-registered rule the answer is still correct, so the scoreboard does not move; the answer-line count does, from sixteen of sixteen to fifteen of sixteen. v3 (third pass) added `rules.md` to that route and to the decline route; in sixteen v3 answers the line is back on every one and the file count stayed at four.

## Where the folder won

- **On the five questions that need the data, questions 3 to 7.** The bare model declined all five in both runs and invented nothing. These are wins on the rule, not on judgment: the question had a checkable answer and only the arm with the data gave one.
- **On question 2, by the grading call above.**
- **Forty-seven of the folder's forty-eight answers ended with the fixed line** (sixteen of sixteen in v1, fifteen of sixteen in v2, sixteen of sixteen in v3): `ANSWER: value | METHOD: methodology section n | SOURCE: file, columns, rows`. A stranger grading the folder reads one line and a section number. Grading the bare model means reading the prose for the number, and on five questions there is none.
- **Fewer words.** Median words per answer: folder 190 and 200, bare model 276 and 254.

## What the bare model did

In all sixteen cold sessions the model looked at an empty working directory, tried to download prices (Yahoo Finance or Stooq in every session, both in fourteen of the sixteen; Alpha Vantage, Tiingo, Financial Modeling Prep, PyPI and GitHub in some), was refused by the sandbox every time, and said so. On questions 3 to 7 it then declined, in both runs: "I'd be guessing, so I won't give one"; "any figure I gave would be made up"; "I'm not going to make up a number". In most of those sessions it said its knowledge ends in June 2026 and offered a script the reader could run with network access. It never produced a figure it did not have. Its failure mode was silence, not invention. Under the pre-registered rule a decline on a question with a checkable answer is wrong, and that is how it is scored; the count of invented numbers, zero, is reported beside it because it is the more important fact about the arm.

Four of the sixteen cold sessions also tried their own run directory inside this repo, the folder that holds the session's settings file, which the sandbox lets a session see. Two listed it with Bash and found a settings file and a system prompt; two used the Glob tool and were refused. Nothing else of this repo is reachable from a session; `PROTOCOL.md` has the probe that shows it. No folder session touched that directory.

## Run-to-run agreement

No verdict changed between run 1 and run 2 in either arm. Wording moved; numbers did not. The differences worth a line: the bare model's second run put "about +27%" in its headline for question 1 and 26.7% in its table; the folder's second run opened files one at a time in five sessions where the first run used one `cat` in seven of eight; the folder's question 8 answer line differed by a clause between runs ("not in the dataset" against "not in the dataset; the data ends 2026-09-30"). In v2 no verdict changed between runs either; the one difference is the missing answer line on run 2's question 8. In v3 no verdict changed and both runs carried the line on every answer; one v3 refusal opened three files instead of four, because a refusal needs no price file.

## What we changed in the folder because of it

One change so far, driven by the one place the folder cost more. The v1 folder arm read every file on every question even though the README's route table names the two or three files a numeric question needs; the README's own "Next" line sent the reader to `identity.md` every time. v2 changed `README.md` only (commit `68aacb2`): the "Next" line now names `rules.md`, the one methodology section and the price file; the route table gained a "Do not open" column; one sentence says reading the whole folder is not the job. No rule, example, convention or number changed, because no number was wrong.

What v2 did, two runs of eight: the same sixteen correct answers; files touched per question fell from seven to four (`README.md`, `rules.md`, the methodology, the price file), the exact set the route table names, in fifteen of sixteen sessions; median words per answer fell from 190 and 200 to 166 and 168; median output tokens from 1,221 and 1,462 to 1,068 and 1,114; seconds did not move. Four files instead of seven is the folder doing what the map says, which v1 did not.

What v2 broke, once: the route for a month outside the window says to read methodology section 11 and nothing else, so in one session (run 2, question 8) the model never opened `rules.md` and answered without the fixed answer line. Content right, shape wrong. That is a map that routed too narrowly.

The second change, v3 (commit `73a6c4c`), added `rules.md` to the two narrow routes and nothing else. Two runs of eight: sixteen correct answers, sixteen answer lines, four files per question (three on one refusal, which needed no price file), median words 178 and 164, seconds and tokens where v2 left them. Three versions, two changes, both to one file, both measured. The folder that ships is v3, and the outside check below ran on it.

Disclosure: both changes were designed in the private pilot, where the same first map produced the same seven-files result and the same second map dropped the same answer line on the same question. Each is applied here only after its cause appeared in this repo's own runs; the commit log shows the order.

## Caveats, stated rather than buried

- **Two runs per arm is a small sample.** Every verdict agreed across runs, which says the pattern is stable, not that it is universal.
- **Cold against folder cannot separate the data from the structure.** Every win here is the data's win. The private pilot ran a third arm, the price file and its dictionary with no folder, and it matched the key on every question, twice. This repo does not repeat that arm; the brief asks for two.
- **The folder was written after the questions existed, by the people who wrote the questions**, and its map was refined in the private pilot against these same questions before this repo began. The git log of this repo shows the control runs before the folder and each map change after the runs that motivated it; the outside check is the only test on questions we did not write.
- **The questions carry their conventions.** To be answerable by a model with nothing, each prompt states the period, the weights and the rebalancing rule. A question that left the convention unstated would test the folder harder, and we did not ask one.
- **A session can see its own run directory.** The runner hands each session a settings file from the run's output folder inside this repo, and the sandbox lets the session list that folder: its settings, its system prompt, and the finished answers of sibling questions in the same run. A probe with the runner's exact flags shows that nothing else is reachable, not the price file, not `questions.md`, not another arm's runs. Four cold sessions and no folder session touched it. The runner was left unchanged so that every scored run in this repo had the same environment; the fix for a future runner is in `PROTOCOL.md`.
- **The path of that directory names the arm** (`control/` or `treatment/`). No session remarked on it; the word "control" appears in two cold answers only inside the quoted path.
- **The sandbox leaked once, in the pilot, before any scored run.** In a smoke test the bare model, blocked from downloading, re-issued two commands with the sandbox switched off, which the default settings allow, and got live prices. The setting that forbids this was in the runner before any scored run, here or there, and every transcript carries a per-question count of such requests; the count is zero everywhere.
- **Claude Code tells every session today's date**, so both arms knew October 2026 was not over. This is identical across arms and is why question 8 caught nobody.
- **Yahoo adjusts past prices retroactively.** The committed CSV is the dataset, not Yahoo; a re-fetch can differ in the last decimal.
- **A model that declines is graded wrong on questions it cannot answer without data.** That was the pre-registered rule. A reader who thinks declining is the right behaviour for a model without data will find the invented-number count, zero, reported beside it.
- **The question 2 verdict** is the one a reader might reverse; both readings are given above with the score each gives.
- **Three folder versions ran, and the changes were made by the people reading the results.** Both changes touched only the map and only how much the model reads; neither could change a number, and none did. Both were designed in the pilot and re-applied here after their causes recurred.
- **The redaction.** The runner replaces the sandbox's own per-command proxy credentials with a placeholder when it saves a transcript, and nothing else; `PROTOCOL.md` says why.

## How to reproduce

```bash
git clone https://github.com/leoxeno/four-asset-desk-control && cd four-asset-desk-control
pip install -r requirements.txt
python3 tools/answer_key.py                     # the expected answers, from the CSV
python3 tools/check_sandbox.py                  # prove the network is sealed on your machine
python3 tools/run_arm.py cold 3 --jobs 8
python3 tools/run_arm.py treatment 3 --jobs 8 --out treatment/v3                                        # the folder as it ships (v3)
git checkout 2227e89 -- README.md && python3 tools/run_arm.py treatment 3 --jobs 8 --out treatment/v1   # the first map
git checkout 68aacb2 -- README.md && python3 tools/run_arm.py treatment 3 --jobs 8 --out treatment/v2   # the second map
git checkout HEAD -- README.md
python3 tools/extract.py treatment/v1/run-3     # digest for grading; verdicts go in grading.yml
python3 tools/score.py                          # the scoreboard from grading.yml
```
